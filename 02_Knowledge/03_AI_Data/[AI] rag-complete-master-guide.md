# 📚 RAG (Retrieval-Augmented Generation) Complete Master Guide

## 1. 개요 (Why)
거대 언어 모델(LLM)은 학습 시점 이후의 최신 정보를 알지 못하며, 사실이 아닌 내용을 그럴듯하게 말하는 환각(Hallucination) 위험이 있습니다. RAG는 모델에게 신뢰할 수 있는 '참고서(Knowledge Base)'를 제공하여, 질문이 들어올 때마다 관련 정보를 실시간으로 찾아보고 답변하게 함으로써 지식의 정확성과 최신성을 보장합니다. 본 노드는 산업용 RAG 시스템의 신뢰도를 결정론적으로 관리하기 위한 아키텍처 표준을 정의합니다.

## 2. 핵심 기술 사양 (Numerical Specs)

| Parameter | Symbol | Value (Tier 1) | Tolerance | Unit |
| :--- | :--- | :--- | :--- | :--- |
| Chunk Size | $L_{chunk}$ | 512 ~ 1024 | ±128 | tokens |
| Top-K Retrieval | $K$ | 3 ~ 10 | N/A | count |
| Vector Dimension | $d$ | 768 ~ 1536 | N/A | dims |
| Latency (Retrieval) | $t_{ret}$ | < 200 | ±20 | ms |
| Faithfulness Score | $S_{faith}$ | > 0.95 | ±0.02 | ratio |

## 3. RAGFidelityEngine: Diagnostic Logic

RAG 시스템의 검색 품질 및 답변 무결성을 진단하는 `RAGFidelityEngine` 로직입니다.

```python
class RAGFidelityEngine:
    def __init__(self, query_vector, doc_vectors, generated_answer):
        self.q = query_vector
        self.docs = doc_vectors # List of vectors
        self.ans = generated_answer

    def diagnose_retrieval_precision(self):
        """질의와 검색된 문서 간의 의미적 유사도(Cosine Similarity) 진단"""
        similarities = [np.dot(self.q, d) / (np.linalg.norm(self.q) * np.linalg.norm(d)) for d in self.docs]
        avg_sim = np.mean(similarities)
        
        if avg_sim < 0.7:
            return f"CRITICAL: Low Retrieval Relevance ({avg_sim:.2f}) - Hallucination Risk High"
        return f"OPTIMAL: High Context Precision ({avg_sim:.2f})"

    def audit_faithfulness(self, fact_entities):
        """생성된 답변이 검색된 문서 내의 팩트(Entities)를 포함하는지 검증"""
        # 검색된 팩트 중 답변에 포함되지 않은 비율 분석
        missing_facts = [f for f in fact_entities if f not in self.ans]
        if len(missing_facts) > 0:
            return f"WARNING: Potential Grounding Failure (Missing: {missing_facts})"
        return "PASS: Answer Fully Grounded in Context"

# Instance Diagnostic
engine = RAGFidelityEngine(query_vector=np.random.rand(768), 
                           doc_vectors=[np.random.rand(768) for _ in range(5)], 
                           generated_answer="The Cpk target for IATF 16949 is 1.67.")
print(engine.diagnose_retrieval_precision())
```

## 4. 분석 프레임워크: RAG Optimization Pipeline
1. **[Semantic Chunking]**: 문장을 단순히 길이로 자르지 않고, 의미적 응집도(Semantic Cohesion)를 기준으로 분할하여 검색 정확도 향상.
2. **[Hybrid Search (BM25 + Vector)]**: 키워드 기반 매칭과 의미 기반 임베딩 검색을 결합하여 고유 명사 및 전문 용어 검색 누락 방지.
3. **[Re-ranking Strategy]**: 1차 검색된 수십 개의 문서 후보를 고성능 Cross-encoder 모델로 재정렬하여 최적의 컨텍스트 선별.

## 5. 스스로 체크 (Self-Audit)
1. 'Hallucination'을 방지하기 위해 프롬프트에 '검색된 내용에 없으면 모른다고 답하라'는 제약을 거는 것이 왜 중요한가?
2. 쿼리 임베딩과 문서 임베딩 모델의 '차원(Dimension)'이 일치해야 하는 물리적 이유는?
3. 검색된 문서가 너무 많을 때(K > 10) 발생하는 'Lost in the Middle' 현상이 답변 품질에 미치는 영향은?
