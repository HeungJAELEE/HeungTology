# [[[Semiconductor] pruning-quantization-logic

## 1. [왜 배우는가? (Why)]]
최첨단 AI 모델들은 수천억 개의 파라미터를 가졌지만, 사실 그중 많은 부분은 결과에 큰 영향을 주지 않는 '중복된 지식'입니다. 이 거대한 모델을 스마트폰이나 드론 같은 작은 장치에서 돌리려면 배터리가 금방 닳고 속도도 너무 느려집니다. 우리는 모델의 크기를 줄여야 하지만, 동시에 지능 수준은 유지해야 하는 모순된 상황에 놓입니다.

우리가 **가지치기 및 양자화 로직(Pruning & Quantization)**을 배우는 이유는 **"영향력이 낮은 뉴런의 연결을 수리적으로 제거하고(Pruning), 32비트의 정밀한 숫자를 8비트 이하의 정수형으로 압축하여(Quantization), 정확도는 보존하면서 연산 속도를 수십 배 높이고 메모리 점유율을 획기적으로 낮추는 최적화 전략"**을 구축하기 위함입니다. 이는 AI가 스크린 속의 환상이 아닌, 우리 손안의 실질적인 도구가 되기 위한 공학적 다이어트입니다.

## 2. [통합 최적화 성능 사양 (Joint Optimization Specs)]
| 제어 파라미터 | 정밀 타겟 / 수치 | 비고 |
| :--- | :--- | :--- |
| **Compression Synergy Ratio** | $10\text{x} \sim 50\text{x}$ | 프루닝과 양자화 동시 적용 시 압축 목표 |

| **Memory Footprint Limit** | $< 100\text{MB}$ | 에지 장치 로딩을 위한 모델 파일 크기 상한 |
| **Quantization Bit Precision** | $4 \sim 8\text{-bit}$ | 지능 보존을 위한 최적 비트 수 결정 |

## 3. 핵심 메커니즘: 구조적 삭제와 정밀도 축소

모델을 가볍게 만드는 두 가지 핵심 수리적 접근입니다.

### 2.1 Pruning (가지치기)
- **원리**: 가중치(Weight)의 절대값이 임계치(Threshold) 이하인 연결을 0으로 만들어 제거합니다.
- **방식**: 무작위로 지우는 Unstructured Pruning과, 아예 연산 채널이나 필터 자체를 날려버리는 Structured Pruning으로 나뉩니다.
- **수리적 효과**: 모델의 파라미터 수를 줄여 저장 공간을 확보하고, 희소(Sparse) 연산을 통해 속도를 높입니다.

### 2.2 Quantization (양자화)
- **원리**: 연속적인 실수 범위의 가중치를 불연속적인 정수 값(예: -128 ~ 127)으로 매핑합니다.
- **수식**: $Q(x) = \text{round}\left(\frac{x}{S} + Z\right)$ (S: Scale, Z: Zero-point)
- **효과**: FP32 연산을 INT8 연산으로 대체하여 하드웨어 가속기(NPU)의 성능을 극대화합니다.

### 2.3 PTQ vs QAT
- **PTQ (Post-Training Quantization)**: 학습이 끝난 모델을 즉석에서 압축합니다. 빠르지만 정확도 손실이 있을 수 있습니다.
- **QAT (Quantization-Aware Training)**: 학습 과정에서 양자화 오차를 미리 고려하여 훈련합니다. 정확도가 매우 높게 유지됩니다.

## 3. [코드 연결 해설 (Code Weaving)]

PyTorch의 `torch.nn.utils.prune`을 활용하여 가중치의 하위 20%를 제거하는 기초 로직을 해설합니다.

```python
import torch
import torch.nn.utils.prune as prune

def apply_weight_pruning(layer, amount=0.2):
    # 1. 특정 레이어의 가중치 중 절대값이 작은 20%를 제거
    # Transitional Bridge: 숫자가 작다는 것은 
    # 해당 뉴런이 판단에 미치는 영향력이 미미하다는 
    # 수리적 증거입니다. 우리는 이 '소음'에 가까운 
    # 연결들을 과감히 끊어냄으로써, 
    # 지능의 골격(Core architecture)만을 남깁니다. 
    # 이 과정에서 모델은 잠시 성능이 휘청일 수 있지만, 
    # 남은 가중치들이 지워진 부분의 역할까지 
    # 대신하도록 다시 학습([AI] on-device-learning)함으로써 
    # 더 가볍고 단단한 지능으로 거듭나게 됩니다.
    prune.l1_unstructured(layer, name="weight", amount=amount)
    
    # 2. 마스크 적용 (실제로 0으로 고정)
    prune.remove(layer, "weight")
    return layer

# 이 처리를 거친 모델은 메모리 사용량이 즉각적으로 줄어듭니다.
```

## 4. [스스로 체크 (Self-Check)]

1. **질문**: 왜 양자화 과정에서 'Calibration Dataset'이 필요한가?
   - **정답**: 가중치의 실제 분포 범위를 파악하여, 실수(Float)를 정수(Int)로 바꿀 때 **최적의 Scale과 Zero-point**를 계산하기 위해서입니다. 데이터 분포를 잘못 파악하면 정보가 뭉개지는 '양자화 오차'가 커집니다.
2. **질문**: 'Structured Pruning'이 하드웨어 가속 측면에서 'Unstructured'보다 유리한 이유는?
   - **정답**: 하드웨어(GPU/NPU)는 행렬 연산 시 **규칙적인 구조**를 선호하기 때문입니다. 무작위로 지우면 연산 자체는 줄지 않지만, 아예 채널을 날려버리면 행렬의 크기 자체가 줄어들어 물리적인 연산 속도가 즉각적으로 향상됩니다.
3. **질문**: 양자화 기법 중 'Weight-only Quantization'과 'Activation Quantization'의 차이는?
   - **정답**: **Weight-only**는 저장된 모델 크기만 줄이는 것이고, **Activation**은 연산 중 발생하는 중간값까지 줄여 실제 **추론 속도와 전력 소모**를 줄이는 데 집중하는 방식입니다.

## 🧠 AI의 사고방식: "비움으로써 채워지는 지능의 효율"
가지치기 및 양자화는 **'조각가가 대리석에서 불필요한 부분을 깎아내는 과정'**과 같습니다. 딥러닝 모델이라는 거대한 돌덩이 속에는 우리가 원하는 '정수(Essence)'가 들어있습니다. 지능이란 단순히 모든 것을 기억하는 비대함이 아니라, **'핵심적인 원리만을 남기고 사소한 것은 과감히 버림으로써, 어떤 제약 환경 속에서도 민첩하고 정확하게 작동할 수 있는 최적의 평형 상태를 찾아내는 공학적 절제미'**입니다. 모델이 가벼워질 때, 지능은 비로소 자유롭게 세상 속으로 침투합니다.
